# 钱钱岛 种子数据方案 DATA-PLAN（v2）

> 项目名：save money / 钱钱岛 Money Island
> 适用规格：[`daily-egg-tower-defense-spec-v2.md`](./daily-egg-tower-defense-spec-v2.md)
> 实现结构：[`code-implementation-guide-v2.md`](./code-implementation-guide-v2.md)（种子生成目标文件为 `src/data/seed.ts`）
> 状态：2026-11-19 按 v2 口径更新；代码尚未接入种子数据，当前新访客打开是空岛。
> 用途：首次打开时按本方案生成种子数据，让评委一打开就能看到一座活的岛，并能直接演示日报、周报、孵蛋和塔防。
> 原则：数字要真实，不要用 99999、不要用 1 元刷图鉴。所有价位都按大学生真实消费写。

- 月预算：不用单独设，只按“周预算 × 4 = 1400 元”在年报里做约数展示
- 初始已收集精灵：18/32（14 普通 + 4 稀有），4 只隐藏款全部未收集
- 演示蛋：最近一个完整周（11-09 至 11-15）总分 80，金蛋，7/7 天，可一键演示孵化
- 今日（11-19，周四）：45 元，3 笔（交通 4 + 外卖 23 + 奶茶 18）
- 当前自然周（11-16 至 11-22）只录到 11-19；塔防演示改用上一个完整周 11-09 至 11-15
- 演示塔防：用 11-09 至 11-15 的账单分 3 波生成怪物，岛血从 100 开始

## 3. 分类占比（120 笔里的大致分布）

- 外卖：32 笔（27%）
- 奶茶：24 笔（20%）
- 日用：18 笔（15%）
- 交通：14 笔（12%）
- 夜宵：10 笔（8%）
- 学习：9 笔（7%）
- 快递：7 笔（6%）
- 娱乐：6 笔（5%）

合计 120 笔。每天 3-5 笔，周末略多，周一略少，不要每天都均匀 4 笔。

## 4. 时间分布

- 2026-10-20 至 11-18：每天 3-5 笔，按上面占比随机
- 11-19 当天：3 笔，4 元（交通）+ 23 元（外卖）+ 18 元（奶茶）= 45 元
- 时间点要真实：早餐 7-9 点、午餐 11-13 点、奶茶 14-16 点、晚餐 17-19 点、夜宵 22-23 点
- 不要出现凌晨 3 点的外卖、不要出现同一分钟两笔
- 不要生成 2026-11-19 之后的账单

## 10. CSV 导入格式（演示版）

用户在支付宝 / 微信导出账单 CSV 后上传解析。按以下列名映射，找不到列就提示用户检查文件，不要静默丢数据。

| CSV 列（常见名） | 映射到 |
|---|---|
| 交易时间 / 交易创建时间 | time |
| 交易对方 / 商品名称 / 备注 | note（用于隐藏款判定） |
| 金额（元） | amount |
| 交易分类 / 类别 | category（按关键词映射到 8 个分类，映射不上默认“日用”并在预览里标出来） |
| 收/支 | 只导入“支出”，收入跳过并在预览里说明 |

导入预览必须显示：总笔数、支出笔数、跳过笔数、金额合计、将新召唤的精灵数（最多 5 只）。
确认后才写入 localStorage，一次导入最多弹出 5 只新精灵。当前代码尚未实现 CSV 导入。

## 11. 生成规则（给实现的硬要求）

- 首次打开按本方案生成种子数据，存进 localStorage；键名按 v2 规格用 `money-island:v1`
- 当前代码仍使用 `money-island:` 前缀的多键存储（settings / bills / summon / eggs / settlements / wishes），迁移时不要直接覆盖用户数据
- 第二次打开不要重复生成，不要覆盖用户后续记的账
- 生成时用固定种子，不要每次随机出完全不同的账单，保证评委和真人测试看到一致的岛
- 所有金额按分存储，界面显示保留 2 位小数；时间统一用 ISO 字符串
- 不要生成未来日期的账单
